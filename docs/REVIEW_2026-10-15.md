## Live activation blockers

The current private preview is a static, device-local demo. The Nest runtime uses bounded process-memory stores. OAuth callback routes documented previously are reserved routes, not implemented live endpoints. Existing token encryption and publishing adapters do not constitute an activated OAuth integration.

No Orbit Supabase project was found in the connected project inventory; the one returned project is StockPilot and was not changed. No social credentials were printed or requested in chat. Before live activation Orbit needs its own durable backend and authenticated workspace membership, HTTPS callback routes, server-managed Meta/Threads app credentials, one-time session-bound OAuth state, encrypted persisted tokens with refresh/revocation, and current-revision approval persisted with publication jobs. Connecting Meta accounts must happen through official owner authorization. A live test needs an explicitly reviewed post and destination, with a returned provider post ID checked once. Do not enable live publishing or expose local-demo authentication to accomplish this prematurely.

Official provider references: https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api and https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api . Facebook Login for Instagram requires a linked professional account/Page; Instagram Login is a distinct route that does not require a Page. Threads has a separate authorization configuration. Confirm scopes/API versions in the selected Meta app before deployment.
